# قاعدة المعرفة الجغرافية لاشتراطات عمارة الساحل الشرقي

نظام يحوّل أدلة الاشتراطات المعمارية وخرائط النطاقات (حاضرة الدمام) إلى قاعدة معرفة
جغرافية رقمية قابلة للاستعلام بالإحداثيات، مع تتبّع كامل للمصدر (المستند، الصفحة،
البند، صورة الصفحة) ونظام مراجعة بشرية.

## ⚠️ تنبيهات جوهرية قبل الاستخدام

1. **الحدود الجغرافية تقريبية (±3 كم)**: تم Georeferencing خرائط الأنماط المعمارية
   بنقاط تحكم **تقديرية** لمعالم ساحلية (ميناء الملك عبدالعزيز، جسر الملك فهد)
   وليست قياسات مساحية. لا تستخدم النتائج لتحديد قطع أراضٍ قبل اعتماد نقاط تحكم
   دقيقة (القالب في `04_georeferencing/control_points/`).
2. **لا تُعتمد العناصر الجديدة تلقائياً**: كل قاعدة أو نطاق جديد يبدأ بحالة
   `pending_review`. عند إعادة بناء القاعدة، يعاد تطبيق تاريخ المراجعة المحفوظ
   على العناصر ذات المعرّفات الثابتة، فلا تضيع القرارات السابقة.
3. **خريطة المنطقة المركزية للدمام (MAP-DMA-03) مربوطة جغرافياً ربطاً تقريبياً**
   مثل بقية الخرائط؛ لا يعني ذلك دقة مساحية. جميع نتائج الخرائط خاضعة لهامش
   عدم اليقين المعلن أعلاه.
4. المصادر الحالية هي أدلة **الطابع المعماري** (أنماط، واجهات، مواد، تكوين) —
   لا تتضمن اشتراطات بنائية كمّية (ارتدادات/نسب بناء) لأنها غير واردة في الملفات
   المتوفرة. أضف أدلة الاشتراطات البلدية لاحقاً وأعد تشغيل الـPipeline.

## أوامر التشغيل (CLI)

```bash
# المرحلة 1: الجرد (sources.csv/json + inventory_report.md)
py -X utf8 -m app.inventory

# المرحلة 3-4: استخراج النصوص وصور الصفحات ثم الاشتراطات
py -X utf8 -m app.extract_all

# المرحلة 5-7: Georeferencing وتحويل المضلعات وQA overlays
py -X utf8 -m app.process_maps

# المرحلة 8-9: الروابط والتعارضات وقاعدة البيانات (SQLite + GeoPackage)
py -X utf8 -m app.build_database

# استعلام بالإحداثيات
py -X utf8 -m app.lookup --lat 26.42 --lon 50.10 --building-type residential_villa

# التصدير (geojson / csv / json / all)
py -X utf8 -m app.export --format all

# تشغيل الخدمة وعارض الخرائط
py -X utf8 -m app.serve        # ثم افتح http://127.0.0.1:8000/

# اختبارات الجودة
py -X utf8 tests/test_quality.py

# تقرير الجودة HTML
py -X utf8 scripts/qa_report.py
```

جميع المراحل **قابلة لإعادة التشغيل** دون تكرار بيانات (IDs مشتقة من بصمات ثابتة).
بناء SQLite وGeoPackage ذري: تُبنى الملفات المؤقتة وتُتحقق سلامتها قبل استبدال
المخرجات السابقة، مع الحفاظ على سجل قرارات المراجعة وإعادة تطبيقه.

## حالة البيانات بعد تدقيق 2026-07-19

- 200 قاعدة مستخرجة من الأدلة الإنجليزية الثلاثة: 154 احتفظت بقرارات اعتماد
  سابقة، و46 قاعدة مصححة أو مستعادة بقيت `pending_review`.
- 25 نطاقاً مفاهيمياً في ملفات GeoJSON، منها 21 هندسة غير فارغة قابلة للاستعلام؛
  الأربعة الباقية تمثل فئات لا تحتوي مضلعات في الخرائط المصدر. النطاقات الـ21
  النشطة احتفظت بقرارات مراجعتها في SQLite وGeoPackage.
- 15 تعارضاً مكانياً: 9 لها قرارات حسم محفوظة، و6 مصنفة آلياً كأشرطة حدودية
  صغيرة. لا يستنتج النظام نطاقاً فائزاً من التداخل وحده.
- جميع الهندسات بإحداثيات WGS84 (`EPSG:4326`) والربط الجغرافي تقريبي بدقة معلنة
  قدرها ±3 كم.

## واجهة API

| Endpoint | الوصف |
|---|---|
| `GET /health` | حالة الخدمة |
| `GET /lookup/location?lat=&lon=` | النطاقات المحتوية للنقطة |
| `GET /lookup/rules?lat=&lon=` | الاشتراطات المنطبقة |
| `GET /lookup/full?lat=&lon=&building_type=` | الاستجابة الكاملة (موقع + اشتراطات + تعارضات + ثقة) |
| `GET /zones/{id}`، `GET /rules/{id}`، `GET /sources/{id}`، `GET /maps/{id}` | تفاصيل عنصر |
| `GET /zones.geojson` | جميع النطاقات |
| `GET /conflicts.geojson` | مناطق التعارض وحالة حسمها |
| `GET /review/pending` | العناصر بانتظار المراجعة |
| `POST /review/rule/{id}`، `POST /review/zone/{id}` | قرار مراجعة `{reviewer, decision, notes}` |
| `POST /review/conflict/{id}` | قرار تعارض دائم مع `winning_zone_id` عند الحسم |

`building_type`: `residential_villa` أو `low_rise_building` أو `mixed_use`.
تتحقق الواجهة من نطاق الإحداثيات، ونوع المبنى/العنصر، وحدود عدد النتائج، واسم
المراجع، وتعيد أخطاء واضحة للمعرّفات أو المدخلات غير الصالحة. تُحفظ قرارات
التعارض في ملف دائم وتُعاد عند بناء قاعدة البيانات.

## عارض الخرائط (المراجعة)

افتح `http://127.0.0.1:8000/` بعد تشغيل الخدمة:
- خريطة OSM مع النطاقات ملونة حسب المستوى، وتشغيل/إخفاء الطبقات.
- انقر أي نقطة أو أدخل إحداثيات → الموقع والنطاقات والاشتراطات مع روابط صور الصفحات.
- أزرار اعتماد/رفض لكل قاعدة ونطاق (تُسجَّل في `review_decisions` مع سجل تغييرات).

## بنية نطاقات الأنماط (المستويات)

| المستوى | الأنماط المسموحة |
|---|---|
| المستوى 1 | تقليدي فقط |
| المستوى 2 | تقليدي + انتقالي |
| المستوى 3 | تقليدي + انتقالي + معاصر |
| مناطق مستثناة | خارج اشتراطات الطابع |

الربط قاعدة↔نطاق آلي حسب تقاطع أنماط القاعدة مع أنماط النطاق، مع أولوية
لخرائط المدن على خريطة الحاضرة (دون حذف القواعد العامة — التعارضات تُسجَّل
في `conflicts` ولا تُحسم تلقائياً).

## ما يحتاج تدخلك (المراجع)

1. **نقاط تحكم دقيقة** لكل خريطة (6-10 نقاط عبر القالب) — ترفع الدقة من ±3 كم
   إلى دقة مساحية. النقطة الاختبارية في الظهران (`26.13, 50.14`) تقع خارج مضلع
   MAP-DMA-04 بنحو 1.3 كم، أي ضمن هامش عدم اليقين المعلن؛ لذلك لم تُزح الحدود
   يدوياً، ويلزم تحسينها بنقاط تحكم مساحية موثوقة.
2. **مراجعة واعتماد** القواعد الـ46 المتبقية بحالة `pending_review` عبر الواجهة؛
   لم تُعتمد القواعد المصححة أو المستعادة تلقائياً.
3. **مراجعة التعارضات الـ15** بين تصنيف خريطة الحاضرة وخرائط المدن، ولا سيما
   التحقق البشري من الأشرطة الحدودية الستة ومن قرارات الحسم التسعة المحفوظة.
4. إضافة مصادر الاشتراطات البلدية الكمية (ارتدادات، نسب بناء...) عند توفرها.
